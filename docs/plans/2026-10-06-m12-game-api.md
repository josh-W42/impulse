# M12 — Engine as a Library: Design + Results

**Date:** 2026-10-06 · **Status:** complete · **Driven by:** solstice G0
(`../solstice/docs/plans/2026-10-06-g0-skeleton.md`, Part A), the first game
built on impulse.

## Why

`impulse-engine` exported only `run(title)`: window and GPU startup, egui,
input, the frame loop and the editor were one private 1,300-line `Running`.
A second program couldn't reuse any of it without copying the browser glue.
Two smaller gaps also blocked a large map: shadows covered a fixed 50 m square
at the origin, and there was no strategy-game camera.

## What shipped

- **`Game` trait and app shell** (`game.rs`, `shell.rs`). The shell owns the
  `Gpu`, `Renderer`, `InputState`, egui context and input, the draw list, and
  the frame loop: surface acquire and recovery, event routing, then
  `update` → `ui` (inside the egui pass) → `draw` → render → present. Games
  get a `Context` (gpu, renderer, window, input, egui, `dt`, `elapsed`, plus
  `aspect()` and `cursor_ndc()`). `run_game(title, make)` starts one; `make`
  runs once the GPU is ready.
- **The editor is now `Sandbox`**, the first `Game`. `run(title)` still starts
  it, so `impulse-demo` is unchanged.
- **`examples/spinning_cube.rs`**: the smallest game. CI compiles it
  (`--all-targets`), so it guards the public API.
- **`Renderer::set_shadow_focus(focus, half_extent)`**: the shadow map
  follows a point; everything within `half_extent` (5–100 m) of it is covered.
  The focus moves in whole shadow texels in light space so edges don't shimmer
  while panning. The default (origin, 25 m) reproduces the old matrix exactly.
- **`RtsCamera`**: focus on the ground, yaw, clamped pitch (0.35–1.45 rad) and
  distance (6–150 m), optional XZ bounds, and default controls (WASD/arrows,
  Q/E rotate, R/F tilt, wheel zoom, middle-drag and touch pan, pinch zoom).
- **Public re-exports:** `egui`, `glam`, `winit`, `impulse_render as render`,
  `InputState`, `FixedTimestep`, `perspective`, `cursor_ray`,
  `DEFAULT_UI_SCALE`.

## Deviations from the plan

- `Context::aspect()` and `cursor_ndc()` were added; both the sandbox and
  solstice needed them.
- Sandbox panel actions now apply at the start of `draw` instead of after the
  draw list was built, so they show one frame sooner.
- Raw mouse motion always reaches `InputState` (before: only in fly mode);
  `end_frame` clears it, so nothing accumulates.
- Two A2 tests were rewritten. Coverage is guaranteed for a *circle* of radius
  `half_extent` (an oblique light's square doesn't contain a ground square's
  corners). Snapping is tested as "the light-space offset is always a whole
  number of texels", since a fixed sub-texel move can legitimately cross a
  rounding boundary. Removing the snap makes that test fail (checked).
- `rts_center_ray_hits_the_focus` allows 1 cm: f32 rounding through the
  inverse projection (near 0.1, far 500) costs ~5 mm at 40 m.

## Verification

- fmt, clippy (native + wasm32, `-D warnings`), 247 workspace tests, 116
  classic-solver tests, physics dependency check, web build.
- Sandbox, checked by the user on native and in the browser: play (grab/throw,
  orbit, pan, zoom), fly mode, edit (select, drag, Shift-drag, Delete, Ctrl+D,
  undo/redo), filter typing, save/load, UI size. Spinning cube example runs.
- WebGPU (Pit, Tower) and WebGL2 (Joints, Tower) in the preview after A1 and
  again after A2: same rendering, shadows present, no console errors.
