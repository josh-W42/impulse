# R1 — HDR Pipeline, MSAA, Bloom: Plan + Results

**Date:** 2026-11-02 · **Status:** hand-checked and merged (PR #5) · **Track:**
[render quality](2026-11-02-render-quality-track.md)

## Why

The scene is shaded and tonemapped in one pass straight into the sRGB
swapchain. Edges are aliased, and nothing brighter than white survives to
glow. Every later track milestone (AO, local lights, emissive spells) wants a
linear HDR buffer to work in.

## Design

```
shadow ─► scene (Rgba16Float, 4× MSAA) ─resolve─► hdr ─► bloom down ×N ─► bloom up ×N-1 ─► composite + tonemap ─► swapchain (sRGB) ─► egui
```

- **Scene target:** `Rgba16Float`, 4× MSAA resolved into a single-sample
  texture. Lit, skinned, sky and line pipelines draw into it at the frame's
  sample count. Exposure stays in the scene shaders; tonemapping moves to the
  composite pass.
- **Bloom:** Jimenez's downsample/upsample chain (CoD: Advanced Warfare),
  as in "physically based bloom": a 13-tap downsample (Karis average on the
  first level against fireflies), a 3×3 tent upsample added into the next
  larger level, no threshold, a small `mix` strength (default 0.04). One
  texture per level (not mips of one texture) so no pass reads the texture
  it writes. This avoids WebGL feedback-loop rules.
- **Composite:** `mix(scene, bloom, strength)`, then Khronos PBR Neutral
  into the swapchain's sRGB view. The tonemap lives in `tonemap.wgsl`, which
  is prepended to both shaders.
- **Fallback:** if the adapter can't render, resolve, blend and filter
  `Rgba16Float` (WebGL2 without `EXT_color_buffer_float`), the scene target
  is `Rgba8UnormSrgb`, the scene shaders tonemap as they do today (a flag in
  `Globals`), and bloom is unavailable. The same passes run either way.
- **API:** `render()` is unchanged, so solstice and Ashen Crown keep
  working. The new surface is `PostSettings { msaa, bloom, bloom_strength,
  exposure }`, `Renderer::{post_settings, set_post_settings,
  hdr_supported}`. Changing the sample count rebuilds the colour pipelines
  lazily in the next `render()`.
- **Sandbox:** a Rendering section with MSAA and bloom toggles, a strength
  slider and an exposure slider. Turning bloom and MSAA off gives today's
  image for comparison.

Known limit: resolving MSAA before tonemapping lets very bright edges (sun
disc behind a silhouette) alias. A tonemap-aware custom resolve is out of
scope.

## Tasks

1. `Gpu` records whether the HDR format and depth format support 4× MSAA,
   resolve, blend and filtering (pure `fn` over `TextureFormatFeatures`,
   unit-tested).
2. `tonemap.wgsl` split out; `finish()` in the scene shaders; `post` flag in
   `Globals`.
3. `post.rs`: frame targets (MSAA colour, resolved colour, depth), bloom
   levels (`bloom_sizes`, unit-tested), composite. `post.wgsl` with naga
   WebGL2 checks.
4. Renderer: colour pipelines built per (format, samples), rebuilt on change;
   render() routes through the post chain.
5. Sandbox Rendering panel.
6. Verify: native debug + release, WebGPU, WebGL2, plus screenshots before
   and after. Measure the frame-time cost.

## Results

Built as designed; `render()` signature unchanged. New code: `post.rs`,
`shaders/post.wgsl`, `shaders/tonemap.wgsl`; colour pipelines are now
`ColorSource::pipelines(format, samples)` in `renderer.rs`.

| Check | Result |
| --- | --- |
| Unit + shader tests | all green: scene-target selection (4), bloom level sizes (2), post shader translates to WebGL2 GLSL |
| clippy (native + wasm32, `-D warnings`) | clean |
| WebGPU (local build, browser pane) | `Rgba16Float`, MSAA on; renders; MSAA toggle rebuilds pipelines with no errors |
| WebGL2 (local build, browser pane) | `Rgba16Float`, MSAA on (`EXT_color_buffer_float` present); renders, no errors |
| Native Vulkan, debug + release | runs with no validation errors |
| SDR fallback, forced natively | `Rgba8UnormSrgb`, MSAA on; runs with no validation errors (image not inspected) |
| solstice, Ashen Crown | `cargo check` clean against this branch; both now get MSAA + bloom by default |

Not done:
- **Frame-time cost not measured.** The browser pane throttles frames, and
  native presents with vsync. A GPU-timestamp measurement is still owed.
- **Toggle comparison not checked by hand.** The pane drops clicks, so the
  before/after screenshots and the native image need a human look.
